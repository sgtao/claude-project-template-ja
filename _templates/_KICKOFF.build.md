# KICKOFF.md — 最初のプロンプト（{{PROJECT_NAME}}）

Claude Code を開き、下の枠の中を最初のメッセージとして渡す。モデルは Opus を勧める（仕様づくりのため）。

```text
SPEC.md を、実装の前に完成させてください。コードはまだ書きません。

依頼：{{GOAL}}
完成物：{{DELIVERABLE}}
使いたい技術：{{STACK}}
始め方：{{MODE_LABEL}}

{{> _KICKOFF.mode.md}}

やること：
1. SPEC.md の [要記入] をすべて埋める
   - 合格条件は、スクリプトか画像で確かめられる形で 10 個以内。形容詞は数値に直す
   - 技術は、この環境で動くことを最小のコードで実際に確かめてから書く。
     使う言語と道具の版（python3 --version など）を確かめ、「実行環境の版」に書く
   - マイルストーンの最初は、SPEC.md の表の M1 の形。以降は各 1〜2 時間の規模
   - リスクを大きい順に 3 つと、その回避策
   - 使う言語が決まったら、成果物の `.gitignore`（セットアップで作成済み）を確かめる。
     「テンプレートの .gitignore にした」と出ていたら、`python3 _tools/gitignore.py --dir <成果物のフォルダ> --langs <言語> --force` で
     github/gitignore の該当ファイル + テンプレートの補完に作り直す
2. python3 _tools/check_spec.py SPEC.md を実行し、不合格を直す
3. 迷う点は、仮の前提を置いて PROGRESS.md に書いて進める。
   仮の前提では仕様が決まらない点だけ、最後にまとめて質問する
4. 仕様の弱点を自分で問い直す（合格条件が空振りしないか、負例で落ちるか、手順と検査が食い違わないか）。
   問い直しのスキル（例：/grill-me）があれば使ってよい
5. SPEC.md の要点を 10 行以内で報告し、確認を待つ
```

SPEC.md を確認したら、次からは `/milestone` で 1 つずつ進める（最初は、SPEC.md のマイルストーン表の M1）。
