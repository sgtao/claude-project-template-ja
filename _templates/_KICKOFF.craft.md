# KICKOFF.md — 最初のプロンプト（{{PROJECT_NAME}}）

過去の作業の実例（入力と出力、作業メモ、使っている表など）を `01_sources/` に置いてから、
Claude Code を開き、下の枠の中を最初のメッセージとして渡す。モデルは Opus を勧める（聞き取りと設計のため）。

```text
PLAYBOOK.md を、手順書やスキルを作る前に完成させてください。成果物はまだ作りません。

依頼：{{GOAL}}
成果物：{{DELIVERABLE}}
形にする範囲：{{CRAFT_TYPE_LABEL}}
作業の様子：{{TASK_PROFILE}}
始め方：{{MODE_LABEL}}

{{> _KICKOFF.mode.md}}

やること：
1. 01_sources/ の実例を一覧して開き、今の手順を番号付きで書き出す。
   実例から分からない手順と判断は、質問の候補として控える
2. PLAYBOOK.md の [要記入] をすべて埋める
   - 判断の基準は「条件 → 結論」の形にし、例外も書く
   - 手順ごとに自動化の水準を決める。迷ったら低いほう（手作業・チェックリスト）を選ぶ
   - 実例から評価ケースを作り、04_evals/cases.csv に書く（正例・境界・負例。result は「未実行」）
   - 合格条件は、数えられる形で 10 個以内
   - 使う言語と道具の版（python3 --version など）を確かめ、「実行環境の版」に書く
3. python3 _tools/check_spec.py PLAYBOOK.md を実行し、不合格を直す
4. 依頼書の弱点を自分で問い直す（判断の基準に穴がないか、負例で本当に止まるか、自動化しすぎていないか）。
   問い直しのスキル（例：/grill-me）があれば使ってよい
5. 手順と判断の基準のうち、実例から分からなかった点だけを、最後にまとめて質問する
6. PLAYBOOK.md の要点を 10 行以内で報告し、確認を待つ
```

PLAYBOOK.md を確認したら、次からは `/milestone` で進める（最初は、実例 1 件を最後まで通す）。
