# next-cycle：版を締めて、次の版の計画を作る

## 手順

1. **締める前の確認**（足りないものは、締める前に済ませるか、ユーザーに確かめる）
   - `git status` が空か（未コミットの変更は、コミットするか、残す理由を聞く）
   - 合格条件の判定（`/verify` の報告）と、未検証の一覧が `PROGRESS.md` にあるか
   - `HANDOFF.md` が今の状態か（古ければ `/handoff` で作り直す）
   - タグ・リリース・push などの承認待ちの操作が、済んだか、まだかを、事実で確かめる
2. **名前を決める**：前の版の名前に合わせる（例 `v0-0-1`）。ユーザーの指定があれば従う。
3. **試す**：`python3 _tools/cycle.py close <名前>` を実行し、写すもの・移すものの一覧を示す。
   続けて書き足す会話の記録（今のこのセッションなど）は `--keep <番号>` で残す。
   版の途中から `05_logs/<名前>/` に計画などを置いていたときは `--merge` を付ける（同じ名前のファイルがあれば止まる）。
   移すファイルは直下から消える（git には残る）ため、一覧を示して承認を得てから次へ進む。
4. **実行する**：`python3 _tools/cycle.py close <名前> --apply`。`05_logs/<名前>/README.md` ができたことを確かめる。
5. **PROGRESS.md を次の版に向けて直す**：現在地を「<次の名前> の計画づくり」に、チェックリストを初期の形に戻す。
   未検証と既知の問題は、消さずに「前の版からの持ち越し」として残す。
   `04_evals/cases.csv` は、締めたときに result が「未実行」に戻っている。次の版で通し直すまで、
   `check_cases.py` は不合格になる（`--allow-pending` で警告にできる）。前の版の結果は note と `05_logs/<名前>/evals/` にある。
6. **計画を始める**：`python3 _tools/cycle.py start <次の名前>` で `PLAN.md` を作り、
   `05_logs/<名前>/` の材料（未検証、未対応の指摘、反映先が空の学び、HANDOFF.md）から 3 節と 4 節を埋める。
   `/retro` を、このとき一緒に提案する（版の区切りは、繰り返しを見つけやすい）。
7. **計画を出して止まる**：PLAN.md の要点を 10 行以内で示し、承認を待つ。本体はまだ変えない。
8. **承認の後**：PLAN.md の 6 節の合格条件と 5 節のマイルストーンを、仕様のファイルに反映する
   （前の版の合格条件は `05_logs/` の写しに残っているので、置き換えてよい）。以降は `/milestone` で進める。
9. コミットする（仕様のファイルの「コミットの方針」に従う）。

## テンプレートに戻す
版を締めたときに、ほかのプロジェクトでも使える学び（検査、手順、ルール）があれば、
テンプレートのリポジトリに戻す案を 1 行で示す（README の「テンプレートを育てる」）。
