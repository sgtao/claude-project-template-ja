# handoff：次のセッションが迷わず始められるようにする

## 手順

1. **材料を集める**：`PROGRESS.md`、仕様のファイル（SPEC.md・BRIEF.md・PLAYBOOK.md）、`PLAN.md`（あれば）、
   `DECISIONS.md` の今日の行、`git status`、`git log --oneline -10`、このセッションの会話の記録。
2. **事実を確かめる**：「済んだ」と書く項目は、コミットや検査の結果で確かめる。
   承認待ち・未実施の操作（push、削除、公開など）は、済んだこととして書かない。未コミットの変更があれば、そのことを書く。
3. **書く**：`_templates/_HANDOFF.md` を写して、直下の `HANDOFF.md` を作る（前のものは git に残るので上書きしてよい。
   未コミットの `HANDOFF.md` があるときは、上書きの前に確かめる）。
   - 先に結論（3 行以内）、済んだこと（コミットの ID 付き）、未検証、承認待ちの操作と条件、次の一手、
     落とし穴（このセッションで失敗したことと避け方）、次のセッションの最初のメッセージ
4. **PROGRESS.md の「次の一手」を、HANDOFF.md と合わせる**。
5. **コミットする**：仕様のファイルの「コミットの方針」に従う。
6. **報告する**：次のセッションの最初のメッセージを、そのまま貼れるように ```text の枠で示す。ほかは 3 行以内。

## 最初のメッセージの書き方
- 読むファイルを順に書く（`HANDOFF.md` → 仕様のファイル → `PROGRESS.md`）
- やることを 1 つに絞り、範囲と、止まる場所（承認が要る操作、人の確認点）を書く
- 「まだ実装しない」「計画を出して止まる」など、止まり方を明記する
- このセッションの会話を読まなくても分かるように、略語や「さっきの」を使わない

## サイクルを締めるとき
版を締めて次の版を始めるときは、`/next-cycle` を使う（HANDOFF.md もそこで `05_logs/` に移る）。
