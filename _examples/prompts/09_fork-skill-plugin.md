# 例 9：手元のスキルを複製して、1 つのプラグインに作り替える（専門作業・複製して改造）

## 元の依頼
> 4 つのスキルを順に呼んで解説資料を作っている。これを 1 度の指示で通るプラグインにしたい

## ヒアリングでの答え方
答えの見本：[`answers/fork-skill-plugin.json`](../answers/fork-skill-plugin.json)

- 始め方：複製して改造（`fork`）。複製元のパスと、写す時点（コミット）を書く
- 同期の方針：決めていなければ「まだ決めていない」でよい。最初の作業で Claude が案を出す
  （追従するなら同期のスクリプトと複製元のテスト、切り離すなら複製元のテストの移し替えが要る）
- 置き場所：成果物を別の git リポジトリにするなら、`03_outputs/<名前>/` と書く（このリポジトリでは .gitignore に入れる）

## PLAYBOOK.md に足すとよい合格条件
```text
- 複製元のテストが、写した時点と同じ件数で通る（確認：各リポジトリの tests を別々のプロセスで実行）
- スキルの名前に接頭辞を付け、複製元と同じ名前のスキルが 0 個（確認：check_skill.py と名前の一覧）
- 実物の入力 3 件（HTML・PDF・YouTube）を 1 度の指示で通し、出力の形の検査が通る（確認：05_evals/ の記録）
- 対話での質問の回数が、計画の上限以内（確認：MANUAL-CHECK.md）
- 複製元のライセンスの表示が README にある
```

## 審査の役割
初めて触るユーザーに、複製元の作者の観点を足す（ライセンスの表示、変えないと決めた点）。

## 人の確認点
同期の方針（追従か切り離しか）と、公開（push、タグ）の前。
版を重ねるときは `/next-cycle` で版ごとの記録を `04_logs/` に締める。
