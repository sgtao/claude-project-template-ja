# 例 7：経費精算のチェックを手順書とスキルにする（専門作業・新規）

## 元の依頼
> 毎月の経費精算のチェックが自分しかできない。新人に引き継げるようにして、できるところは自動にしたい

## ヒアリングでの答え方
答えの見本：[`answers/expense-check-skill.json`](../answers/expense-check-skill.json)

- 対象：専門作業（`craft`）。形にする範囲は「両方」（手順書を正本にし、照合だけをスクリプトとスキルにする）
- 資料：過去 3 か月の申請の写しと、担当者の作業メモを `01_sources/` に置く。個人名は仮名にする
- 作業の様子：誰が・頻度・所要時間を書く（自動化の効果を、所要時間で数えるため）

## PLAYBOOK.md に足すとよい合格条件
```text
- 過去 3 か月の申請（30 件）で、判定が担当者の判定と一致する（確認：check_cases.py。不合格 0 件）
- 負例（領収書の日付が申請の月の外、上限を超える金額、二重の申請）の 3 件で、「確認する」か「差し戻す」で止まる
- 新人が手順書だけで 1 か月分を 90 分以内に終えられる（確認：MANUAL-CHECK.md で計測）
- スキルの description に呼び出しの言葉が 3 つ以上（確認：check_skill.py）
- 社内規程にない判断を、スキルが自分で決めない（確認：境界のケースで「確認する」が返る）
```

## 審査の役割
その作業の熟練者（判断の基準の穴）と、初めてその作業をする新人（手順書だけで行えるか）の 2 回。

## 人の確認点
判断の基準（とくに例外）と、どの手順を自動にするか（自動化の水準）は、担当者が決める。
