# 例 1：ブラウザゲーム（制作）

## 元の依頼
> ブラウザで動くシューティングゲームを作って

## ヒアリングでの答え方
答えの見本：[`answers/browser-game.json`](../answers/browser-game.json)

- 完成物：「単一の HTML ファイル」のように、起動のしかたが決まる形で答える
- 合格の目安：「最後まで遊べる」「やり直せる」のように、遊ぶ人の言葉でよい

## SPEC.md に足すとよい合格条件
```text
- 単一の HTML で起動する。操作、勝敗の条件、スコアを画面の中に表示する
- 状態の更新を描画から分け、update(state, input, dt) を単体でテストできる（確認：単体テスト）
- 自動プレイで、開始 → 移動 → 衝突 → 得点 → ゲームオーバー → 再開を通す（確認：Playwright）
- 入力の列を固定した再生で、毎回同じスコアになる（確認：3 回の再生で一致）
- コンソールのエラー 0、平均 55fps 以上（確認：計測スクリプト）
```

## マイルストーンの切り方
M1 自機が動き、弾が出て、敵 1 種に当たる（最後まで通る版）→ M2 スコアとゲームオーバーと再開 →
M3 敵の種類とステージ → M4 効果音と見た目 → M5 調整と最終の検査

## 新規の制作でだけ足す一文
`CLAUDE.md` に「あなたはこのコードベースの所有者兼長期メンテナーです」と足すと、重複の整理が進みやすい。
頼んでいない変更も増えるので、足したら差分を必ず読む。既存のコードを直す仕事では足さない。
