# 例 3：Blender の映像、音楽、コードで描く絵（制作）

どれも「モデルは音も絵も直接は確かめられない」分野。数値と画像で確かめられる条件に直す。

## Blender の映像
> 自転車に乗る写実的なペリカンの Blender 映像を作って

```text
- blender -b（画面なし）で最後まで動く Python スクリプトである
- 低解像度のキーフレーム 6 枚 → 全編の低画質版 → 最終レンダリング、の順に進む
- 全フレームで検査する：車輪の回転と移動距離の差が 5% 以内、メッシュの貫通 0、主役が画角の中
- 最終レンダリングの時間を、低画質版の実測から見積もり、承認を求める
```

## 音楽
> オリジナルの曲を作って

```text
- BPM、調、小節数、構成（イントロ／A／B／サビの小節割り）を、先に表で決める
- 出力は WAV（44.1kHz）。クリッピング 0、ピーク -1dBFS 以下、2 秒を超える無音がない（確認：スクリプト）
- スペクトログラムと波形を PNG で出し、構成の表のとおりに展開していることを確かめる
```
音の良し悪しは、最後に人が聴いて決める。人の確認点に「試聴」を入れる。

## コードで描く絵
> 写実的な油絵を、コードで描いて

```text
- 先に、画家のペルソナ（技法、色の癖、構図の好み）を 5 行で決めて SPEC.md に書く
- 下塗り → 中間 → 細部の 3 層で描き、各層の終わりに PNG を出して、構図と明暗を確かめる
- 乱数のシードを固定し、同じ絵を再生成できる（確認：2 回の出力のハッシュが一致）
- 筆致の数、キャンバスの大きさを数値で決める（例：70 万ストローク、4096x4096）
```

## 共通の注意
- 既存のキャラクターや歌声の素材を使う場合は、利用の条件を人が確かめる
- 有料のレンダリングや長い処理は、`CLAUDE.md` の承認の対象
